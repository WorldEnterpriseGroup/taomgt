Use before the next meeting

Good tools make the question harder to avoid.

These are prompts for making a condition, decision, boundary, or learning loop visible. They are designed to be used in a working session—not admired as another framework.

Start with the tool that names the uncertainty you are carrying. The linked route adds the context, practice, and next question.

Six working instruments

Choose the blank that needs filling.

Open the executive library →
01 / Readiness↗

Change impact canvas

Use it when

A new program is being described by its milestones, but not by what changes for each role.

First prompt

Write the promise, affected work, changed decision, local variation, and first signal.

Follow the thread →
02 / Solution strategy↗

Decision record

Use it when

Teams are debating options without preserving the intent, evidence, boundary, or return point.

First prompt

Record the condition, decision, alternatives, owner, evidence, constraints, and review moment.

Follow the thread →
03 / Governance↗

Operating-model drift board

Use it when

The organization has several versions of how decisions, standards, and exceptions are actually handled.

First prompt

Compare the intended model with the lived model, then choose one boundary to make explicit.

Follow the thread →
04 / Modernization↗

Continuity canvas

Use it when

A platform or process change could expose a customer, cash, control, or service promise.

First prompt

Name what must remain true, where exposure rises, and which uncertainty must be reduced first.

Follow the thread →
05 / Responsible AI↗

AI guardrail canvas

Use it when

A promising use case has a compelling demo but no clear owner, stop condition, or human boundary.

First prompt

Define the decision, allowed data, evidence, reviewer authority, failure modes, and pause path.

Follow the thread →
06 / Field practice↗

Gemba observation sheet

Use it when

The problem is being explained from a distance and the people doing the work have a different story.

First prompt

Follow one real case, record the sequence, notice the queue and workaround, and close with one owned experiment.

Follow the thread →

A compact decision record

Keep intent attached to the move.

When a decision travels through a program, the original condition often disappears. Use these six fields to keep the choice legible.

Decision record fields and guiding questions
FieldQuestion
ConditionWhat business reality requires a decision now?
DecisionWhat choice was made, and which meaningful alternative was not?
OwnerWho is accountable for the result and who can act?
EvidenceWhat is observed, assumed, or still uncertain?
BoundaryWhat is shared, local, permitted, prohibited, or reversible?
ReturnWhen will the evidence be reviewed and what can change?
